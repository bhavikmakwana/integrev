Duplicate Deal Checker

Application Overview & Documentation

Executive Summary: Duplicate Deal Checker is a web-based application designed to help sales teams manage deal submissions and identify potential duplicate entries. The system uses fingerprinting and scoring algorithms to flag suspicious submissions while maintaining a complete audit trail for administrative review.

1. Application Purpose

The integrev system serves as a centralized deal management platform that:

  • Prevents Duplicate Submissions - Automatically detects and flags potentially duplicate deals using advanced scoring algorithms
  • Streamlines Deal Management - Provides an intuitive interface for sales teams to submit, view, and manage deals
  • Enables Admin Review - Gives administrators tools to review flagged deals and approve/reject submissions
  • Maintains Data Integrity - Ensures accurate deal records with validation and duplicate checking

2. Why We Need It

  • Risk Mitigation - Duplicate deals can lead to conflicting commitments, revenue confusion, and customer relationship issues
  • Efficiency - Automated duplicate detection reduces manual review time and human error
  • Data Quality - Maintains a clean, reliable database of active deals
  • Compliance - Provides audit trails and approval workflows for deal governance
  • Cost Savings - Prevents wasted resources on duplicate follow-ups and customer dissatisfaction

3. Backend Architecture

Technology Stack: Node.js, Express.js, PostgreSQL

Key Components:

  • API Server - RESTful endpoints for deal management secured with CORS
  • Database Layer - PostgreSQL with JSONB support for flexible cost matrices
  • Duplicate Detection Engine - Fingerprint and scoring utilities for identifying similar deals
  • Admin Workflow - Flagged deals review and approval/rejection system

Core API Endpoints:

  • POST /api/deals/precheck – Compute duplicate score and reasoning
  • POST /api/deals/submit – Submit new deal (auto-flagged if score exceeds threshold)
  • GET /api/deals – List all deals with pagination
  • GET /api/deals/:id – Get individual deal details
  • PUT /api/deals/:id – Update deal information
  • DELETE /api/deals/:id – Remove deal from system
  • GET /api/admin/flagged – List flagged deals requiring review
  • POST /api/admin/review – Approve/reject flagged deals with justification

Database Schema - Deals Table:

  • Customer Name, Product, Quantity (min/max), Quantity Band
  • Location, Expected Close Date, Deal Owner
  • Fingerprint (for duplicate detection)
  • Status (submitted, flagged, approved, rejected)
  • Cost Matrix (JSONB for flexible pricing data)
  • Justification, Created Timestamp

4. Frontend Architecture

Technology Stack: React, Parcel, HTML5, CSS3

Key User Interface Views:

  • Deal Form – Submit new deals with comprehensive information including product details and cost matrix
  • List View – Browse, search, filter, and manage submitted deals with full CRUD operations
  • Admin Dashboard – Review flagged deals, approve/reject submissions, and add justifications

Features:

  • Real-time duplicate scoring preview during form entry
  • Form validation with user-friendly error messages
  • Responsive UI design for desktop and mobile devices
  • Intuitive navigation between different workflow views
  • Cost matrix JSON parsing and validation

5. Application Workflow

  1. Sales User submits a deal via the Deal Form with customer, product, quantity, location, and cost details
  2. System runs precheck analysis using fingerprinting and scoring algorithms to detect potential duplicates
  3. Deal is submitted with status of either "submitted" or "flagged" based on duplicate score threshold
  4. Admin reviews flagged deals in the Admin Dashboard and examines scoring rationale
  5. Admin approves or rejects each flagged deal with optional justification notes
  6. Deal status is updated accordingly in the system for tracking and reporting
